runtime change was required**: Laravel is the sole owner/orchestrator of Composite Readiness,
and FastAPI's only role on this path is `POST /api/v1/skill-match` (`skill-match-v1`).

### The three identifiers, now distinct on every row

```
composite_algorithm_version = composite-readiness-v1   # STRUCTURE (which parts / how they aggregate)
configuration_version       = config-v{n}              # NUMBERS  (weights, cap, band thresholds)
algorithm_version           = skill-match-v1           # FastAPI's component algorithm
```

Rule: tuning a weight/cap/band bumps `config-*` only. Adding a component or changing the
exclusion/redistribution policy bumps `composite-readiness-*`.

### Deliberately NOT done

- **No public response field** for the composite version (ADR-001 §4). Stored in audit metadata
  only; exposing it is additive and can happen any time, back-filling could not.
- **No back-fill** of historical `configuration_version` rows — forward-only.
- **No change to `skill-gap-v1`** — it stays a published, independently versioned algorithm.
  Laravel's Composite never calls it, so its 60.0 cap cannot conflict with Laravel's 69.0.

## DS token set in Render + the contract re-verified live

Data Science sent `DATA_SCIENCE_SERVICE_TOKEN` and the user set it in **Render**.

**Local `.env` still has NO token** → local `readiness/calculate` and `intelligence/calculate`
still return 503 `*_NOT_CONFIGURED` before any network call. Only the Render deployment is
unblocked. `DATA_SCIENCE_SERVICE_URL` locally already points at the deployed service
(`https://skillspan-intelligence.onrender.com`), so the token is the only missing local piece.

Token wiring confirmed: both clients use `->withToken($token)`, which sends
`Authorization: Bearer {token}` — so the env var must hold the **raw token**, not `Bearer xxx`.
`DataScienceClient` trims surrounding whitespace; `IntelligenceClient` trims too.

`Dockerfile` CMD runs `php artisan config:cache` **at container start**, so env vars are read at
boot — a Render env change needs a redeploy/restart to take effect.
