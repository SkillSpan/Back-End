## ⚠️ INCIDENT — `database/migrations` wiped mid-session
All **79 migration files vanished from the working tree** within milliseconds of a single `git rm` of ONE
file. Verified NOT caused by my command:
- 79 **unstaged** deletions, all under `database/migrations`, nothing else touched.
- No `.git` lock, no merge/rebase/cherry-pick in progress, no stash, reflog showed only the 3 pre-existing
  commits → no git operation had run.
- Cause remains unidentified — most likely an external process (IDE / file watcher / concurrent tool).

**Recovery:** confirmed the files were unmodified vs HEAD (tree was clean, so nothing local to lose), then
`git checkout -- database/migrations`. All 79 restored; suite re-run → 201 passed. Directory survived
subsequent test runs (no active deletion loop).

**Lesson for this repo:** if `git status` suddenly shows a mass deletion of a tracked directory, check
`git status --short | grep '^ D'` to separate unstaged (external) from staged (mine), verify no lock/stash/
reflog activity, then restore from the index with `git checkout -- <dir>`. Never `rm -rf` to "clean up".
