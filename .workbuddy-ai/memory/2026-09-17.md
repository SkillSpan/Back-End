## Environment gotchas (cost real time today)

1. **`git push` / `git fetch` silently SIGTERM (exit 1, no output) with the managed
   git.** Cause: the managed PortableGit at
   `C:/Users/HP/.workbuddy-ai/binaries/PortableGit/versions/1.2.0/...` has **no
   `git-remote-*` helpers at all**, so HTTPS transport cannot start.
   **Workaround: use the system Git for Windows for any network git operation:**
   ```bash
   SGIT="/c/Program Files/Git/cmd/git"
   "$SGIT" push origin feature/authentication
   ```
   Local-only operations (`status`, `log`, `commit`, `diff`) work fine with the
   managed git. Network is not the problem — `curl https://github.com` returns 200.

2. **A `git commit` was SIGTERM'd mid-ref-update and left the branch ref file
   missing** (`.git/refs/heads/feature/authentication` gone) while `HEAD` still
   pointed at it → git reported *"your current branch does not have any commits yet"*.
   **No data was lost**: the commit object and `.git/logs/HEAD` reflog both survived.
   Recovery is to re-point the ref, e.g.
   `git update-ref refs/heads/feature/authentication <sha>` (or write the file
   directly). Diagnose with `git cat-file -t <sha>` + the reflog before assuming loss.

3. **Bash PATH has no `php`** — every artisan/pint/test command needs
   `export PATH="/c/xampp/php:$PATH"` first. Pint also needs `COLUMNS=120`.

4. **Pint's `reg.exe` size probe is blacklisted** by the sandbox and prints a scary
   "PROGRAM BLOCKED BY SECURITY POLICY" block. It is harmless — Pint still reports
   PASS. Do not retry or work around it.

5. **Never fire parallel `Edit` calls at the same file.** Each is a
   read-modify-write; they silently drop all but one while each reports success.
   Redo them sequentially.
