### The real contract

```
POST /chat   { user_id: str, message: str(1..2000), context: str|null }
          -> { reply: str, provider_used: "gemini"|"groq"|"cerebras"|null, timestamp: ISO8601 }
GET  /health -> { "status": "ok" }
```
Failover Gemini → Groq → Cerebras, 30 s per attempt, `temperature=0.2`, `max_output_tokens=1024`.
422 on Pydantic validation. **200 with `FALLBACK_REPLY` and `provider_used=null` when all providers
fail** (deliberate, for the UI). 500 handler also returns the fallback. No auth, no request-id.
Files: `main.py`, `models.py`, `config.py`, `prompt.py`, `providers.py`. Not a git repo (only a
`chatbot.zip`); `.env` holds three live API keys and is correctly gitignored.

### Why it does not just drop in

`prompt.py` grounds the bot on **SkillSpan documentation** ("Base your answer solely on the official
SkillSpan documentation provided as context"; if absent, it must reply "I don't have enough
information…"). There is **no field for the learner's own data**. So US-REC-01's core promise —
explain *my* readiness, *my* gaps — needs a decision: either Laravel composes the learner's data into
the prompt (→ personal data reaches three external LLMs, exactly what §12.5 governs), or the service
gains a field for it. **Not mine to choose.**

`user_id` is accepted, logged, and never used — it is not an identity, so BR-11 is enforced entirely
by Laravel.

### Mismatches with the Laravel client (all in `chatbot-integration-review.md`)

1. Sends `{context_snapshot, question, request_id}`; service wants `{user_id, message, context}`.
2. Reads `$response['algorithm_version']`; no such field (closest is `SYSTEM_PROMPT_VERSION`, which
   the service does **not** return).
3. **Does not relay `reply` to the client** — I conflated "Laravel must not *generate* prose" (the
   rule) with "must not *relay* prose" (which I invented). As built, the UI gets no answer.
4. `context` means retrieved *documentation*, not the learner's personal snapshot.
5. Assumes a service token + `X-Request-ID`; the service has neither.
6. Treats any non-null reply as `SUCCEEDED` — so an all-providers-down outage would be audited as a
   **success** (`provider_used: null` is the signal Laravel must branch on).

Docblock and failure message corrected in `70829a2`; the stable code is unchanged and the review
lists the decisions needed before wiring.

### ⚠️ The frontend calls the chatbot service DIRECTLY

`.env` has `CORS_ALLOWED_ORIGINS=…,https://skillspan-iota.vercel.app` — the **deployed Vercel
frontend**. So the browser calls `/chat` itself, contradicting the README's own
`React -> Laravel -> service` diagram. Consequences:

1. **The §12.5 gate is bypassable.** A browser-composed request never passes through Laravel, so
   learner data could reach the LLM with no gate. A gate on one of two doors is not a gate.
2. **A shared token cannot work** while the browser calls directly — a token shipped to the browser
   is public. Hence optional, not required (requiring it would break the deployed frontend).
3. **CORS is not access control** — any `curl` can call `/chat` today.

The real problem is that the system is Laravel-mediated and browser-direct **at the same time**.

### ⚠️ RAG is blocked on a missing corpus

"Full RAG in the service" needs a corpus, a pipeline, and prompt wiring. The pipeline I can build;
**the corpus does not exist.** A full `find` over `/e/SkillSpan` for `*.md`/`*.pdf`/`*.txt` returns
only developer docs (READMEs, `docs/api/skill_gap_api.md`, session notes) — no SkillSpan user
documentation, no Help Center content. But the system prompt says answers must come *"solely from the
official SkillSpan documentation provided as context"*. **Do not invent the corpus** — a bot
answering confidently from fabricated docs is the exact failure the grounding rules prevent.

Embeddings could use Gemini (`text-embedding-*`) via the existing `GEMINI_API_KEY`, so no new vendor;
for this corpus size an in-process index beats a hosted vector DB. Decide whether retrieval lives in
the service (stateless design breaks, `context` becomes a redundant second channel) or in Laravel
(service stays stateless, `context` stays the only channel — closer to the current architecture).

## RAG implemented in the chatbot service (`E:/SkillSpan/chatbot`)

Chose "RAG كامل بالخدمة" — so retrieval lives **in the service**, not in Laravel. Contradicts the
stateless argument in `chatbot-integration-review.md` §9, but the corpus is *public platform
documentation*, not learner data, so it does not widen the §12.5 surface for learners.

New: `rag/chunking.py` (pure: paragraph packing → sentence split → hard-split fallback, + overlap),
`rag/embeddings.py` (`Embedder` Protocol + `GeminiEmbedder`, `RETRIEVAL_DOCUMENT` vs
`RETRIEVAL_QUERY` separate), `rag/index.py` (JSON in-process `VectorIndex`, cosine), `rag/retrieval.py`
(request-path `Retriever`), `rag/ingest.py` (`--stats` / `--check` / build), `CORPUS.md`,
`corpus/.gitkeep`. Wiring: `main.py` retrieves only when the caller sent no `context`; `models.py`
gained `retrieval` on `/health`; `config.py` gained the RAG settings + `retrieval_configured`.

Key decisions: **fail soft** (missing/stale/mismatched index or embedder outage → no context, turn
still succeeds — never a 500); **caller `context` wins** so the change is additive; **an index built
by another model is refused at load**, because mismatched vectors return plausible nonsense rather
than erroring; **off by default**.

⚠️ **RAG creates a new external-data flow**: the corpus is now sent to Gemini on every question, so
§12.5 applies to *the corpus*. `CORPUS.md` is deliberately **outside** `corpus/` — anything inside is
ingested, including a guidelines file.

Status: **retrieval is complete and inert.** The corpus (the §9 blocker) still does not exist, so this
grounds nothing yet. Also documented the deployment gap: `index.json` is gitignored, so Render needs
`python -m rag.ingest` in the build command or `RAG_ENABLED=true` yields `retrieval: "unavailable"`.
Added `SERVICE_TOKEN` + `RAG_ENABLED` to `render.yaml` (the former was documented but missing).

Tests: **88 passing** (was 29). New `tests/test_chunking.py`, `tests/test_index.py`,
`tests/test_retrieval.py`; `conftest.py` now provides a deterministic `FakeEmbedder`.
