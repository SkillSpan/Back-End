## Two problems, only one visible

`ci.yml` runs **Pint before PHPUnit**, so the style failure hid the fact that the test
suite was also broken. Fixing Pint alone would have moved the red light, not removed it.

## 1. Pint: `concat_space` in `bootstrap/app.php`

The file had `__DIR__ . '/../routes/web.php'` — spaces around the concatenation. There is
**no `pint.json`** in the repo, so Pint uses its default `laravel` preset, whose
`concat_space` is `none`: it wants `__DIR__.'/...'`.

The previous attempt (`c91c75f`, *"fixed:extra space in app.php(boot strap)"*) did **not**
fix it — it only inserted a stray `/**s */` comment between `)` and `->withMiddleware(`.
Removed that comment as well.

## 2. Five `ReadinessTest` failures (502 instead of 201)

The fixture `successResponse()` still returned the **old `/skill-gap` shape**.
`d87040e` migrated the integration to `/skill-match v1` and the tests were never updated.

New required top-level keys (missing ones throw `DATA_SCIENCE_INVALID_RESPONSE` 502):

```
student_profile_id, career_role_id, career_role_version, user_id, target_role,
algorithm_version, weight_configuration_version, original_weight_total,
normalized_weight_total, weighted_achieved_total, weighted_required_total,
skill_match_score, total_skills, met_skills, partial_skills,
not_required_skills, skill_results
```

New required per-`skill_result` keys:

```
skill_id, skill_name, current_level, required_level, importance_weight,
normalized_importance_weight, achieved_level, match_ratio, is_critical, status
```

Behaviour changes worth remembering:

- `status` values changed from `met`/`gap` to **`met`/`partial`/`not_required`**.
- The validator **cross-checks every `skill_result` against the payload Laravel actually
  sent** (skill_name, current_level, required_level, importance_weight, is_critical) and
  re-derives `normalized_importance_weight`, `achieved_level`, `match_ratio` and `status`
  itself. So a fixture can no longer invent numbers — it has to mirror the payload.
- **`skill_match_score` is FastAPI's value and IS the skill_match component** used by
  `ReadinessService::calculate()` (`$skillMatch = (float) $result['skill_match_score']`).
  The old test comment claimed the component came from a local `SkillMatchService`
  calculation — that is wrong and was corrected. `SkillMatchService` exists but is only
  used by `SkillMatchController`, not by the readiness flow.

Rewrote the fixture to build the v1 contract and to **derive** `skill_match_score`
(`round(weightedAchieved / weightedRequired * 100, 2)`) rather than hardcode it, so it
cannot silently drift from the levels and weights the validator checks.

For the `createScenario()` data — SQL `4.0/0.45/critical/2.5`, Python `4.0/0.30/critical/3.5`,
Power BI `4.0/0.25/4.0` — this yields `skill_match_score = 79.38`, which is what the
existing assertions (`75.6`, `82.0`, `74.0`) were written against. Arithmetic confirmed:
`79.38*.65 + 50*.20 + 90*.10 + 100*.05 = 75.60`.

## Side finding

check it was written for. It now exercises what it intends.
