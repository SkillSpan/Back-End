## Deliberately NOT changed (reported instead)

**`trustProxies(at: '*')` in `bootstrap/app.php`.** Trusting every proxy means
`X-Forwarded-For` is honoured from any client, so `$request->ip()` is spoofable whenever
Render's edge appends rather than replaces the header. The admin-login throttle is keyed
`email|ip`, so rotating a fake XFF defeats the 5-attempt lockout. The targeted hardening is to
drop `HEADER_X_FORWARDED_FOR` from the trusted set and keep HOST/PORT/PROTO (which is what the
419 fix actually needs) — but that changes `$request->ip()` for throttling and logging and
depends on Render's proxy behaviour, so it needs an explicit decision rather than a silent
edit.

# CORRECTION — the `trustProxies(at: '*')` warning above was overstated

The user asked me to explain that warning, so I verified it against the installed framework
instead of relying on recall. **Two things I had asserted were wrong.**

## 1. `at: '*'` does NOT mean "trust every IP"

`Illuminate\Http\Middleware\TrustProxies::setTrustedProxyIpAddresses()`:

```php
if ($trustedIps === '*' || $trustedIps === '**') {
    return $this->setTrustedProxyIpAddressesToTheCallingIp($request);
}
// -> setTrustedProxies([$request->server->get('REMOTE_ADDR')], $headers)
```

In Laravel 11/12, `'*'` resolves to **the calling IP only** — a single trusted hop. It is not
`0.0.0.0/0`. (Symfony's `Request::setTrustedProxies()` has no `'*'` handling at all; passing
the literal string through would match nothing, which is what my first, wrong probe showed.)

So `at: '*'` is the **conservative** setting, and it is the correct one for Render.

## 2. IP spoofing only happens if the edge passes the header through

Empirically verified with a throwaway test (since deleted). Trusted = `[REMOTE_ADDR]`:

| edge behaviour | `X-Forwarded-For` reaching the app | `$request->ip()` |
| --- | --- | --- |
| replaces | `203.0.113.9` | `203.0.113.9` — correct |
| appends | `1.2.3.4, 203.0.113.9` | `203.0.113.9` — correct |
| passes through | `1.2.3.4` | `1.2.3.4` — **spoofed** |

Symfony returns the **rightmost untrusted** entry. The edge's own IP is the trusted one, so
when the edge appends the real client IP, that is the rightmost untrusted value and it wins —
the client's forgery sits to the left and is ignored. **Spoofing therefore requires the edge to
forward a client-supplied header verbatim, which standard proxies do not do.**

Also verified: the 419 fix **does** work — with `PROTO` trusted,
`X-Forwarded-Proto: https` gives `isSecure() = true` / `scheme = https`; without it,
`false` / `http`.

## Net effect

My earlier claim that "rotating a fake `X-Forwarded-For` defeats the 5-attempt lockout" was
**overstated**. The realistic risk is low. No code change is warranted; `at: '*'` should stay.
The residual question — does Render append or pass through? — is answerable from the app's own
logs, since `AdminAuthController::reject()` logs `'ip' => $request->ip()`.
