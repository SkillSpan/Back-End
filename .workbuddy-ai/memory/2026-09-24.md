# 2026-09-24

## Fixed the `intelligence/*` integration break — commit `49e56b1`

`POST /api/v1/intelligence/calculate` called three Data Science paths that **do not exist**:
`/api/v1/intelligence/{skill-gap,readiness,roadmap}`. The deployed service exposes **no
`/api/v1/intelligence/*` namespace at all**, so every real calculation 404'd while all 300 tests
stayed green — the fakes answered whatever URL was requested, and a fake cannot catch a wrong URL.

### The deployed contract (verified, not inferred)

`https://skillspan-intelligence.onrender.com` → `GET /openapi.json` is the authoritative source.
Live paths: `skill-gap`, `skill-match`, `baseline`, `practical-experience`, `profile-completeness`,
`assessment-reliability`, `skill-confidence/calculate`, `career-role-configuration/validate`.
Live algorithm versions: `skill-match-v1`, `skill-gap-v1`, `skill-confidence-v1`.

**Key discovery: `/api/v1/skill-gap` IS the "intelligence" endpoint.** Its `SkillGapResponse`
returns the per-skill gaps **and** the readiness block in one body (`readiness_score`,
`base_readiness_score`, `critical_skill_cap_applied`, `critical_skill_readiness_cap`,
`critical_skill_gap_count`, `critical_skill_names`, `total_skills`, `met_skills`,
`skills_with_gap`). Its `skill_results[]` shape matches `IntelligenceResponseValidator::validateSkillGap`
field-for-field. So this was never a missing feature — a wrong path prefix plus one redundant call.

Its request (`SkillGapRequest`) is **FLAT**: `student_profile_id`, `career_role_id`,
`career_role_version`, `user_id`, `target_role`, `skills[]` where each skill is exactly
`skill_id`, `skill_name`, `current_level`, `required_level`, `importance_weight`, `is_critical`
(`SkillLevel`). Laravel was sending its nested `learner`/`role` envelope verbatim → would 422.

Two flows, two contracts — do not conflate them:
- **Composite Readiness** (`ReadinessService` / `DataScienceClient`) → `/api/v1/skill-match`
  (`skill-match-v1`); Laravel owns the composite weights *and* the cap (69.0).
- **Intelligence** (`IntelligenceService` / `IntelligenceClient`) → `/api/v1/skill-gap`
  (`skill-gap-v1`); the service returns readiness + its own cap (60.0).

### What changed

- `skill_gap_path` default → `/api/v1/skill-gap`. Removed `readiness_path` and
  `calculateReadiness()` entirely (no standalone readiness endpoint exists).
- `IntelligenceClient::toSkillGapRequest()` maps the canonical nested payload onto the flat
  contract, sending **only declared fields** — never relying on the service to ignore unknown keys.
  The nested payload stays the snapshot record and the validator's identity reference.
- `IntelligenceService`: one call; `$readiness = $skillGap`; both contracts still validated
  independently, so a response satisfying one and not the other is still rejected.
- Roadmap path/body documented as **UNVERIFIED** (no endpoint deployed in any form); gate stays off.
- `algorithmVersion` now resolved from the service response only — the service echoes its own
  version, so Laravel must never record the value it asked for.

### Bug I introduced and caught

Going flat made `IntelligenceClient`'s structured logs read `null` for `student_profile_id`,
`career_role_id`, `career_role_version` — they still read the nested shape. Nothing failed; the
logs just stopped being useful. Fixed with `correlationContext()` (reads both shapes) and pinned
by a `Log::spy()` test. **Lesson: after changing a payload shape, check the logs, not just tests.**

## Verified: the DS token is NOT the only blocker — and not even a real one

Ran Laravel's **real** payload builder + client + validators against the deployed service, stopping
before persistence (nothing written to the DB):

```
role          : #3 Data Analyst (4 skills)
evaluations   : 5 of 4
payload built : OK (nested internal shape)
live response : algorithm_version=skill-gap-v1 total_skills=4 met_skills=0 skills_with_gap=4
validateSkillGap   : PASSED
validateReadiness  : PASSED
```

The contract alignment is therefore proven **end to end against the live service**, not just unit-tested.
`readiness_score=0` is legitimate: profile #86 has all four Data Analyst skills evaluated, but every
level sits below the required level.

### The deployed service does not enforce auth at all

`POST /api/v1/{skill-gap,skill-match,baseline}` with **no `Authorization` header** returns **422**
(validation), never 401. So `DATA_SCIENCE_SERVICE_TOKEN` is a **Laravel-side-only** requirement —
`resolvedServiceToken()` fails closed on empty, but the service ignores whatever is sent. **Any
non-empty value unblocks it; no need to wait for Data Science to issue one.**

⚠️ **Security gap:** the service is publicly callable by anyone. US-INT-01 §4 assumes a mandatory
service credential and `INTEGRATION_README.md` says the calls are "all authenticated" — neither is
true of the deployment.

### The real remaining blocker is data, not configuration

- **101 student profiles, 0 with `primary_career_role_id`** → omitting `career_role_id` in the request
  falls back to that null column and yields 422 `CAREER_ROLE_REQUIRED`. Pass it explicitly.
- **Only 9 `SkillEvaluation` rows exist in total, all on profile #86** → the other 100 profiles cannot
  use the feature at all (422 `ASSESSMENT_INCOMPLETE`).
- Profile #86 fully covers role #1 (Frontend, 4 skills) and role #3 (Data Analyst, 4 skills);
  role #2 (Backend) is missing skills 9 and 10.
