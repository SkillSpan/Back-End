## Defects fixed
1. **Total-cap dropped coverage.** Old code did `sortByDesc(is_critical)->take($cap)`, silently removing a non-critical skill's *only* question while still reporting `covered: true`. Replaced with `capPreservingCoverage()`: pass 1 reserves one question per skill (critical/heaviest first), pass 2 spends spare budget on extra questions. When `distinctSkills > max_total_questions` → new `422 INSUFFICIENT_QUESTION_CAPACITY`.
2. **Snapshot wasn't really immutable.** Only the question↔skill mapping was frozen; `question_text`/`item_type`/`options` were read from the live (mutable) item row. Added frozen `item_id`, `item_type`, `question_text`, `options` columns to `baseline_question_snapshots`; retrieval + answer validation now read the snapshot (live fallback only for legacy rows, fail-closed).
3. **No question content field existed anywhere.** Added nullable `question_text` to `baseline_assessment_items` + seeder real prompts; exposed on the assessment API and internal items endpoint. Null when unauthored — never invent text.
4. **Uniqueness blocked multiple roles.** Was `(student, type, version)`; re-scoped to include `career_role_id` (migration 000005).
5. **`question_ids` vs `item_id` ambiguity.** Documented the single identifier namespace: item-bank `item_id` string (e.g. `"sql-001"`) used by client `question_id`, API `item_id`, and DS `question_ids[]`/`responses[].question_id`. Numeric PK stays internal.
6. **DS validation gaps.** Added `INTELLIGENCE_SKILL_MISMATCH` (skill_id must agree with slug), explicit rejection of empty `skills`, and confirmed partial results persist as-returned with no fabricated evaluations.
7–8. Regression tests + full verification.

## Finalization pass (Tasks A–F)

### Task A — snapshot integrity (the real fix)
`baseline_question_snapshots` had `cascadeOnDelete()` on `baseline_assessment_item_id` AND `skill_id`, so deleting a bank question or a skill **destroyed assessment history**. New migration `2026_09_28_000006_protect_baseline_snapshot_integrity`:
- `baseline_assessment_item_id` → nullable + `ON DELETE SET NULL` (snapshot detaches; frozen content keeps it readable/submittable).
- `skill_id` → `ON DELETE RESTRICT` (refuse the delete; don't orphan).
- `baseline_assessment_id` + `career_role_id` keep CASCADE (parent owns its snapshots).
- **Dropped `bqs_assessment_item_unique`** — with nullable item refs, NULLs stop colliding so the index would silently enforce nothing.
- SQLite can't ALTER an FK in place; the driver rebuilds the table. Verified via `PRAGMA foreign_key_list` in tests.
